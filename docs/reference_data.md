# Reference data

Everything a refinement needs that is not the measurement: the starting
model, the refinement parameter files, and the R-free flag set.
It lives in `reference_data/` **in this repository**, it is versioned, and
a config names it as `${REPO}/reference_data/...` rather than by absolute
path.

## Why this file exists

On 19 November three gate architectures were refined on hewl_1118 and
came out at R-free 0.1793, 0.1840 and 0.1875 — a spread of 0.0082, with
the baseline apparently best.
The comparison was worthless.
Each arm had **generated its own R-free set**, and the cost of doing that
is about 0.008 in R-free on weak Laue data: the entire spread.

The cause was not a missing capability.
`reference_data/hewl_1118_rfree.mtz` and
`laue_refine_pass{1,2}_fixedfree.eff` already existed and already solved
it, and `scripts/make_rfree_flags.py` already generated the flags.
The pipeline config pointed at
`/n/holylabs/.../integrato_refac/integrator/reference_data/laue_refine_pass1.eff`
— the flag-generating variant, in a checkout two months behind the one
running — so the fixed-flag pair sat unused.

Hence the two rules at the top of this file: in the repository, and named
relative to the checkout.

## What is in `reference_data/`

| file | what it is |
|---|---|
| `hewl_1118_rfree.mtz` | the canonical R-free flag set for hewl_1118: 29,061 reflections, one `R-free-flags` column, complete over the ASU |
| `laue_refine_pass1_fixedfree.eff` | phenix 2.0 parameters, pass 1, reading that flag set (`generate = False`) |
| `laue_refine_pass2_fixedfree.eff` | the same for pass 2 |
| `laue_refine_pass1.eff`, `laue_refine_pass2.eff` | the flag-GENERATING pair. Kept because runs before 19 November used them and their numbers cannot be read without knowing that. **Do not use them for a comparison.** |
| `custom_refinement_param_{1,2}_poly.eff` | the deposited Laue parameters these descend from, in the 1.20 form phenix 2.0 rejects |
| `shaken_9b7c.pdb` | the starting model, perturbed from 9b7c so refinement has somewhere to go |
| `9b7c.pdb` | the deposited model |

## How the R-free flags were made

By `scripts/make_rfree_flags.py`, and the properties that matter are all
deliberate:

- **Complete over the ASU to `--dmin`.** No merged MTZ can be missing a
  reflection the flag file knows about, so no two MTZs can disagree about
  which reflections are free. This is what makes arms, epochs, resolution
  shells and phenix versions comparable.
- **A uniform random subset at a fixed seed**, so the file is reproducible
  from the command alone.
- **Value 1 is the test set**, matching `test_flag_value = 1` in the eff
  files.
- **Not anomalous.** phenix applies a flag to both Bijvoet mates, which is
  what keeps a Friedel pair on the same side of the split.

To regenerate — which should not be necessary, and changes every R-free
already measured:

```bash
uv run python scripts/make_rfree_flags.py --help     # the current options
```

A regenerated set is a different set.
Numbers from before and after cannot be compared, so regenerate only when
every arm is being refined again.

## Using it

The pipeline config names all four, and `run_pipeline.load_cfg` expands
`${REPO}` to `INTEGRATOR_ROOT` or to the checkout the script is in:

```yaml
phenix:
  eff1:  ${REPO}/reference_data/laue_refine_pass1_fixedfree.eff
  eff2:  ${REPO}/reference_data/laue_refine_pass2_fixedfree.eff
  rfree: ${REPO}/reference_data/hewl_1118_rfree.mtz
  pdb:   ${REPO}/reference_data/shaken_9b7c.pdb
```

With `rfree` set, both refinement passes read that one flag set.
Without it, pass 1 generates flags and pass 2 inherits them, which is
self-consistent within a run and incomparable between runs.

PDZ2 does the same thing by a different route, because its merge is the
deposited eight-file careless call rather than the pipeline's:
`scripts/poly/pdz2/pdz2_refine_prep.py` writes one flag set over the union
of the arms it is given, stores it as `shared_free_flags.csv` beside the
refinements, and **reuses it** when it is already there. Adding an arm
later therefore scores it on the same held-out reflections. Its
`--regenerate-flags` is correct only when every arm is being redone.

## Adding a dataset

1. Generate one flag set for it with `scripts/make_rfree_flags.py`,
   complete to the resolution the refinements will use.
2. Commit it to `reference_data/`. It is a few hundred kilobytes and it is
   the thing that makes every later number comparable.
3. Copy the `_fixedfree` eff pair, point `r_free_flags.file_name` at the
   new set, and commit those too.
4. Name all of it in the pipeline config as `${REPO}/reference_data/...`.

## What is deliberately NOT here

Measurements: merged MTZs, refined models, prediction parquets, peak
tables. Those are outputs, they are large, and they are regenerated by the
chain that produced them. `docs/figures/data/` holds the small reduced
tables the figures read, and those come off netscratch, which is
purge-eligible.
